# Google Play「資料安全性」表單填寫草稿（D-12）

> **草稿，送出前請 D 與 A 確認。** 依目前程式實際蒐集的資料整理（對照 [隱私權政策草稿](privacy-policy.md)）。Play Console 的題目與分類名稱可能調整，以實際畫面為準；標【待確認】的地方要先決定。

## 總覽題

| 題目 | 答案 | 依據 |
|---|---|---|
| 應用程式是否收集或分享任何必要的使用者資料類型？ | 是 | 登入、分享經驗、辦理進度等 |
| 傳輸中的資料是否加密？ | 是 | 前端與 API 一律 HTTPS（Cloud Run），Firebase 也是 HTTPS |
| 是否提供使用者要求刪除資料的方式？ | 是 | App 內「我的 → 帳號 → 刪除帳號」；網頁 `/account-deletion`（不需登入即可查看說明） |
| 帳號刪除網址 | `https://<正式網域>/account-deletion` 【待確認：正式網域，目前是 run.app 網址】 | `backend/app/static/account-deletion.html` |

「分享」在 Play 的定義是傳給第三方。交給服務供應商代為處理的不算分享，例如 Google Cloud、Firebase 驗證、Gemini API，所以下面「分享」一律填**否**。【待確認：Gemini 方案，免費方案可能讓 Google 用內容改善產品，若是免費方案要重新評估】

## 資料類型

| Play 分類 → 類型 | 收集 | 必要／選用 | 用途（Play 選項） | 說明 |
|---|---|---|---|---|
| 個人資訊 → 電子郵件地址 | 是 | 必要（要使用登入功能時） | 帳戶管理 | Google 登入由 Firebase Authentication 處理，Firebase 專案會存 Email；我們的資料庫只存 Firebase 內部 ID，不存 Email |
| 個人資訊 → 姓名 | 是 | 必要（同上） | 帳戶管理 | Firebase 會存 Google 帳號顯示名稱；App 與資料庫不使用、不顯示 |
| 個人資訊 → 使用者 ID | 是 | 必要（同上） | 帳戶管理、應用程式功能 | 帳號編號（Firebase UID 對應） |
| 應用程式活動 → 其他使用者原創內容 | 是 | 選用 | 應用程式功能 | 分享的經驗原話與 AI 摘要（匿名公開）、卡關與差異回報的文字、檢舉理由 |
| 應用程式活動 → 應用程式互動 | 是 | 選用 | 應用程式功能、數據分析 | 辦理步驟進度、反應（有幫助／我也遇過）、封鎖；使用日期與開過哪些經驗（只記日期，用於整體成效統計） |
| 應用程式活動 → 應用程式內搜尋紀錄 | 否 | — | — | 搜尋關鍵字不儲存 |
| 應用程式活動 → 其他操作 | 是 | 選用 | 應用程式功能 | 對 AI 助理的提問：只暫存在伺服器記憶體（約 2 小時、最近幾輪），可勾選「資料只會暫時處理」 |
| 應用程式資訊與效能 → 診斷資料 | 是 | 必要 | 應用程式功能（防濫用、排除故障） | 伺服器紀錄含 IP 位址與錯誤；【待確認：保留天數】 |
| 應用程式資訊與效能 → 當機紀錄 | 否（目前） | — | — | 若之後接 Firebase Crashlytics（A-8），改為「是」 |
| 位置、聯絡人、相片、檔案、日曆、健康、財務、訊息、裝置 ID | 否 | — | — | App 沒有要求這些權限 |
